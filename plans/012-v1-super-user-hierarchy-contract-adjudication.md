## 8. Audit and transaction guarantees

**HUMAN-DECIDED —** IA create, suspend and reactivate require real actor/target identity, supported institute, transactional mutation and required audit. Preserve existing audit history; fail closed when required audit cannot be recorded. No schema change is authorized here.

**PROPOSED —** Exact mutation actions: `SUPER_USER_INSTITUTE_ADMIN_CREATE`, `SUPER_USER_INSTITUTE_ADMIN_SUSPEND`, `SUPER_USER_INSTITUTE_ADMIN_REACTIVATE`. `adminId` is the actual chosen authenticated SUPER_USER User.id; `targetId` is the created/resolved actual IA User.id. For create previousActive=null; for reactivate sessionPurgeCount=0 and no session restore. Request reference is a server correlation value, not a credential. **PROPOSED —** Scoped read actions are `SUPER_USER_INSTITUTE_ADMIN_LIST` and `SUPER_USER_INSTITUTE_ADMIN_DETAIL`; list actor/self target, detail actor/IA target, metadata restricted to contractVersion, selected institute/id, outcome ALLOWED and server request reference. Their audits are separate from existing academic list/detail audit actions. No universal legacy-denial audit requirement is invented.

**PROPOSED —** Use the existing db singleton and transaction-bound client exclusively. A missing target, conflict, denied actor, session-purge error, audit insert error or failed commit produces no successful DTO. Definite failure rolls back all contained changes. Ambiguous commit may have committed: withhold success, preserve a safe correlation reference, and reconcile before replay. Do not report rollback without evidence or claim DB-level immutable audit enforcement.
