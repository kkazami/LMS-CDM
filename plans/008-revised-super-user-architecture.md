## Exact successful-read audit transaction

Use the existing `{db}` singleton with PrismaPg/pg Pool, not a new client or database backend. Intended call: interactive `db.$transaction(callback, {isolationLevel: 'RepeatableRead', maxWait: 5000, timeout: 10000})`. This is a proposed implementation contract, not a transaction executed in this task.

Inside the callback, use **tx only** for session/user revalidation, selected Institute, active scoped Course/related records and AuditLog insert. Do not call a helper that writes through global db or an independent Pool. No parallel/global cached query, external executor/network request or streaming side effect in the callback. RepeatableRead supplies a single database snapshot for authorization/resource/data consistency; it does not promise instant observation of a revocation committed after snapshot admission. The chosen actor/session is checked in the same snapshot, and no alternative identity is selected.

Order:

1. Validate canonical actor/SUPER_USER capability and supported server-selected institute; acquire the controlled transaction and revalidate the actual session/user.
2. Resolve Institute and active Course with actual institute predicate; read only allowlisted fields/related records using tx. No courseCode selection or student/grade/attempt/answer data query.
3. Validate all required current metadata approvals against this exact snapshot and request-pinned approval version; construct the entire DTO server-locally. Any denial/projection/approval failure throws before ALLOWED insert and results in rollback/no DTO.
4. Insert the required AuditLog through tx with only actor/self target, exact action, selected institute, scoped courseId for detail and outcome ALLOWED. Do not log rejected/raw descriptive values or approval details.
5. Await the **whole** `$transaction` promise, including successful COMMIT. Only then may the route/page receive a successful DTO and serialize/render it. Revalidate approval-version/expiry admission before delivering; any ambiguity withholds result. No shared cache or stream of data before this await.

List action is SUPER_USER_ACADEMIC_OVERSIGHT_READ; detail is SUPER_USER_COURSE_SUPERVISION_READ. adminId and targetId both equal the actual Super User; metadata remains a JSON-encoded String as in the schema. A safe failure exposes neither DTO nor private RSC body. Existing audit rows are never updated/deleted; no database-level immutability or universal new legacy-403 audit is claimed.

ALLOWED records a successfully authorized audited read attempt, not guaranteed network delivery. A connection failure/ambiguous COMMIT produces no DTO and no automatic transaction replay; an audit may already be committed. Do not assert it rolled back without evidence or retry into duplicate audit rows. Client network/render failure after commit cannot be atomically rolled back with the DB. Review these delivery/commit boundaries explicitly.

Source-level transaction feasibility is established against the installed 7.9.1 adapter/client: `PrismaPgAdapter.startTransaction` acquires a pool connection and executes BEGIN/SET TRANSACTION ISOLATION LEVEL; `options.usePhantomQuery=false`; the installed Prisma client transaction manager emits COMMIT/ROLLBACK SQL and awaits transaction completion; adapter commit/rollback releases that connection. Existing bulkAssignInstructor already uses interactive tx. No runtime atomicity, rollback or connection-failure test has been run here. If the future service cannot preserve tx-only queries/write, await commit and safe failure with this adapter, stop and report the exact limitation; do not describe a separate global createAuditLog call as transactional.

## Exact critical-boundary rules

The JSON matrix is the operation-level source of truth; rules below clarify special cases and prevent generic “add a guard” remediation:

- **Generic course reads:** actor role is STUDENT with actual APPROVED Enrollment, instructor alias with Course.instructorId=actor.id, or ADMIN system authority; non-Admin home institute equals actual course. Query children through that course, including syllabusItemId/submissionId mismatch checks; students see own submissions only, instructors/Admin only the authorized course. SUPER_USER/UNKNOWN returns 403 before private reads.
- **Teaching/grading/enrollment/groups/attachments:** actual instructor alias + assigned course + institute or ADMIN; every group/member/announcement/item/submission/grade rule/template belongs to the same authorized parent. Student work requires STUDENT + enrollment + own submission; attachmentId belongs to that actual submission. No parent ID supplied for revalidation can authorize an unrelated child. Grading, notifications, EXP/badges, deletion and cache work follow the checks.
- **Creation and auto-assignment:** instructor course creation is allowed in actual home institute and assigns the real actor. `bulkAssignInstructor` permits ADMIN authority or instructor self-assignment only to an actual course already owned/just created by the actor, with actual target role/institute checks. This preserves the current instructorCreateCourse call chain; an Admin-only helper would otherwise break legitimate creation. Generated join codes require recognized teaching/Admin creation capability, never SUPER_USER.
- **Workspace:** personal note/task/event writes require actual creator ownership and institute. Shared course scheduling requires assigned instructor/Admin and actual linked course; students cannot edit shared teaching schedules. All SUPER_USER workspace operations are denied before parse/read/write. No Calendar redesign is authorized.
- **Activities/CodeLab/Judge0:** ICS from persisted institute, never a program claim; SUPER_USER/UNKNOWN denied first. Own freeform code execution uses actor-owned input/session with recognized legacy role. Persisted template/assessment execution additionally requires real course enrollment/assignment/Admin and actual owned attempt. Student submission/progress/milestone uses real owned prior work and same enrolled course; supplied score/title/seed/studentId is not authority. Instructor rejection resolves ActivitySubmission→Template→Course and target member; alert/commend without courseId must infer an actual shared assigned course, not accept user existence alone. - **Inline actions:** each createTemplate/saveTemplate authenticates at invocation and resolves its closure Course/template/item through persisted assignment/institute before parsing JSON, creating/updating assessment records, revalidation or redirects. - **Callable skills:** reauthenticate actual actor at every exported use-server entry; actorId must equal real actor or fail. Post/submission/comment/RepoLink/CI references resolve through actual course/post relationship and stored cohort/instructor/anonymous visibility. Mutations require owned link/author and appropriate student submission or instructor/Admin authority. Course-linked owner/repo/ref/path must match actual authorized link before outbound calls. - **Public/support:** anonymous leaderboard/health/institutes and webhook are reviewed-but-unchanged exceptions. Login/logout/me are exact Super User support. Authenticated SUPER_USER cannot use profile/settings/change-password/refresh/sessions/notifications/OAuth or public recovery/register paths to obtain management rights. Truly anonymous recovery/register protocol remains unchanged. CORS/OPTIONS grants no resource capability. Admin reauthentication and existing audit actions remain intact.

For protected operations, missing/invalid/inactive authentication is 401, denied role/capability is 403, and absent/foreign/non-owned parent/child is a uniform safe 404.
