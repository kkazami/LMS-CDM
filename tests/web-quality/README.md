# Web quality regression checks

Run `node --import tsx --test tests/web-quality/security.test.cjs tests/web-quality/academic.test.cjs` for isolated handler/validation tests. Run `node --import tsx tests/web-quality/integration.mjs` for owned-loopback PostgreSQL migration, authorization, concurrency, rollback and rotation scenarios.

The integration runner starts and stops its own verified PostgreSQL fixture. Never substitute a configured/live LMS database. Session identity selection and Next navigation are injected; business/resource guards, the migration, Prisma queries and transactions are real. These tests are not browser, live-login or load-capacity evidence.

Results are retained under ignored `tmp/web-quality/`. Deployment instructions are in `docs/quality/sprint-1-deployment.md`.

Sprint 2 adds `sessions.test.cjs` and `resources.test.cjs` to the Node command. Run `node --import tsx tests/web-quality/sprint2.mjs` for the owned database, additive migration rehearsal, 400-student/100-assignment gradebook measurement, isolated production build and HTTPS Playwright matrix. It does not read dotenv, reuse a running development server, send invitations or connect to a configured LMS database. Windows needs PowerShell 7 and the verified PostgreSQL fixture already used by the roster tests. It creates and stops its own cluster/server and disposes only its guarded source-copy directory. Evidence is retained under `tmp/roster-import/sprint2-*`.

Install test runtimes with `pnpm exec playwright install firefox webkit`; Chrome is used through the installed `chrome` channel. The dedicated Playwright configuration refuses absent/unknown targets: its state file and run token are supplied by the owned runner, rather than a production URL. Browser tests use real login, cookies, APIs and server actions. Monaco's installed distribution is served unchanged at its configured CDN URLs in the CSP check; this proves editor/policy compatibility, not CDN availability. The local clamd protocol fixture proves integration and failure handling, not real malware recognition. The separate Node resource tests cover rejected/infected/error verdicts. Live scanner/hosting/storage verification and concurrent load belong to Sprint 3.

Sprint 3: `node tests/web-quality/test.mjs` runs the product regressions and writes JUnit to `tmp/web-quality/product-tests.xml`. `node --import tsx tests/web-quality/sprint3.mjs` performs the actual 400-row student import, five courses, four 500-row enrollment batches, retry/resume assertions and a real logical backup/restore to a separate owned database. It compares every application/security table, including representative grades, attachments and private-file bytes. No dotenv/live database is used.

Set `WEB_QUALITY_LOCAL_LOAD=1` only for the owned Sprint 2 runner to append short 50→100→250→400→1,000-user diagnostics on the production HTTPS fixture. It compares two and eight connections per owned app process, restarting the same build/database and stopping each profile on its first failing workload. These use 998 students, a professor, an administrator and 99,800 historical grades with pre-provisioned sessions; each 20-second run is a read-heavy HTTP workload, not a browser, sustained capacity or production claim. Resource samples are in the owned run's `server-metrics.jsonl`. Production still defaults to two connections; any `DATABASE_POOL_MAX` override requires a known aggregate provider budget.

`load.mjs` accepts only explicit reviewed synthetic staging configuration; the main LMS is not an acceptable load target. `staging.example.json` contains placeholders and separate ordinary/deadline/upload/CodeLab contracts. `load-report.mjs` summarizes percentiles/failures and optionally owned process metrics. `restore-check.mjs` performs a read-only comparison of an operator-restored separate owned synthetic target; it never executes a destructive restore. See [operator procedure](../../docs/quality/sprint-3-operations.md) for configuration, safety limits, realistic data assertions, recovery and deployment requirements.

The new `web-quality.yml` CI covers product regressions/type/build, scoped production advisories and configured development-container scans. It does not replace actual staging/provider/human evidence or the independent engineering-harness release gates.
