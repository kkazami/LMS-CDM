# Sprint 1 permitted test scope

[allowed-tests.json](allowed-tests.json) is the explicit 13-file scope for the Sprint 1 fixture. It is not an audit coverage claim or permission to run a wildcard/full suite. The manifest includes baseline calendar/leaderboard/risk/navigation fixtures, alias controls, the new metadata-only export tests, CodeLab/grading/Arduino/MFA compatibility units and patched dependency API smoke checks.

The run recorded in [Sprint 1 results](../../docs/security/sprint-1-results.md) uses a disposable source copy, a separate frozen dependency install, current-schema generated Prisma, a no-network container, no dotenv/real credentials, read-only tools/source input, scratch-local generated files and bounded CPU/memory/process/file/time. Provider and persistence interfaces are explicit in-memory doubles. No production database or provider is required. These tests do not prove real database grant enforcement or deployed MFA/provider isolation.

For reproduction, use the listed files as **individual argv values** to Node's test runner with `--test-concurrency=1`; use the repository's `tests/security/typescript-register.cjs` for the Linux offline loader, or the normal web TSX configuration in an equivalently approved environment. Generate Prisma from the same schema before compilation. Installed Linux tool binaries must match the JavaScript package versions; do not download tools during target execution. The recorded command, source hashes and safe environment are in the corresponding `tmp/security-sprint-1/*/receipt.json` files. Their metadata summary is retained in the results record.

Do not invoke `tests/security/run-audit-regressions.ps1`, `-FullChecks`, `tests/web-quality/test.mjs`, generic root test discovery, or the complete harness/integration suite for this sprint: they can select previously blocked validation work. Forms, attendance, uploads/assets, auth_core, mobile_storage and engineering provider/runner validation stay blocked. Ordinary shared interfaces in these permitted units are not a new review of those hypotheses.

The export audit tests mock the existing administrator/row-read boundaries deliberately and test **only** the new logging contract: exact metadata allowlist, unchanged download, zero-row count, awaited persistence, safe failure and no success event on denial/read failure. Original tenant/field/session regression evidence remains unchanged and is not re-established by these mocks.
