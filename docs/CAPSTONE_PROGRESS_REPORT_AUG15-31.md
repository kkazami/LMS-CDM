**Project:** Multi-Institute Learning Management System (LMS)

## 1. Key Contributions

### Mobile App V1 Foundation
During this period, I started building the first working version of our mobile application using Expo and React Native. I set up the main structure of the app, including the login system, different themes for ICS, IBE, and ITE, and the student and instructor dashboards.

I also worked on the course workspace, which includes the **Stream, Classwork, People, and Grades** sections. The assignments were also brought together so that the mobile app follows the same workflow as our web-based LMS.

### Project Tracking and Organization
To improve how we manage the project, I set up **GitHub Projects** for our development tasks, feature backlog, sprint work, and code-related deliverables.

For the manuscript, I also set up **Trello** so we could keep track of chapters, revisions, and other writing tasks.

### Helping the Team Use Our Tools
I also guided my group members on how to use GitHub Projects and Trello properly. I showed them how to create and update tasks, change task statuses, connect pull requests, and keep track of their assigned work.

This helped make it easier to see what everyone was working on and what still needed to be done.

## 2. Challenges Encountered

### Internet Outage
One of the biggest problems I experienced during this period was losing internet access for six straight days. This affected my ability to push and pull changes from the repository and prevented me from doing some of the cloud-based testing.

During the outage, I focused on working on parts of the application that I could continue without internet access. Once the connection was restored, I had to put in extra time to catch up on the work that was delayed.

### Keeping Everyone on Track
Another challenge was keeping the different capstone groups on track. Since our LMS is being developed by three groups from different academic programs, some members from the other groups had not made much progress and were also not giving regular updates.

I noticed that this could become a bigger problem later in the project, so I called an alignment meeting to discuss the issues, check everyone's progress, and make sure each member understood their responsibilities.

The main goal was to get everyone moving again and make sure that the work of one group would not delay the others.
