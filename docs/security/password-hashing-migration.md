# Password hashing migration

Sprint 5 connects the shared writer and local policy to the synthetic self-service change path for ordinary roles. Production mode retains the existing policy and prevents downgrade of stored Argon2id credentials through this route. Other writer families, reviewed corpus coverage and rollback qualification remain release prerequisites. [Writer qualification](identity-rollout-qualification.md)

Sprint 4 adds dual verification to password login, self-service password change authentication, Google-link password confirmation, administrator password confirmation and the protected institute-administrator reauthentication reader. The shared Node service accepts existing bcrypt and the supported Argon2id profile. Older passwords retain their established bcrypt behavior. The helper uses NFC for new-format credentials, a random 16-byte salt, a 32-byte output, 19 MiB memory, two passes and parallelism one. It allows two concurrent Argon2id jobs per Node process, validates the stored PHC profile before native work and rejects oversize Argon inputs. Benchmark the total memory and contention across deployed functions before enabling writes. [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

| Stage | State | Release requirement |
|---|---|---|
| A. Readers | Implemented locally for account-password consumers above. | Verify the Linux native binary in the produced artifact, deploy readers to every compatible host and prepare a rollback revision with the same reader. Keep bcrypt for unrelated PINs and OTPs. |
| B. New policy | Tested policy primitive. Production setters retain their existing formats. | Provide a reviewed versioned offline list of SHA-256 password digests, confirm refresh and outage ownership, integrate the same policy in every setter and compatible client, and verify the official password-change contract. Empty blocklist input is rejected. |
| C. Migration | Eligibility logic only. No account hash is rewritten. | Verify/write within the existing account transaction by matching user ID and expected bcrypt hash. Use an explicit password-change path for an input at or above 72 UTF-8 bytes or one affected by normalization. Finish protected SQL-writer and recovery compatibility before switching writes. |

The candidate policy uses 15 code points for password-only admission, 8 where MFA is actually mandatory, up to 128 code points and 512 UTF-8 bytes. It accepts spaces and Unicode without composition rules or truncation. Offline digest membership avoids an external password query. The fixture list is synthetic and does not establish a production compromised-password corpus. The privacy screen recommends changing a password when compromise is suspected. Keep paste, autofill and password managers supported as remaining client forms are reviewed. [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html)

Protected SQL procedures currently require bcrypt syntax, and privileged MFA binds session proof to credential identity. Coordinate all writers, database guards, account locking and recovery before enabling Argon2id writes. The previously blocked recovery validation stays excluded. Avoid an opportunistic privileged rehash before reviewed proof revocation and reissuance are ready. On rollback, stop new-format writes and keep dual readers. Preserve existing Argon2id hashes. A bcrypt-only release cannot safely serve migrated accounts.

The final local fixture timed four sequential native Argon2id jobs at 108 ms total under the bounded Linux test runner. This microbenchmark leaves cold starts, peak process RSS, concurrency across functions and actual hosting cost unverified. [Verification record](sprint-4-verification.json)
