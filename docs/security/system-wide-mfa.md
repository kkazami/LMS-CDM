# System-wide MFA implementation boundary

Administrators and Super Users retain their required TOTP, encrypted factor state, challenge-to-session transition and recovery codes. The existing `admin-mfa` code and migrations remain authoritative. Sprint 4 adds a recent completed session requirement to self-service sign-out from all devices. No instructor or student enrollment and enforcement was activated. Existing local administrator tests are retained. [Administrator rollout](admin-mfa-production-rollout.md)

The ordinary-role pilot is held at the authentication contract prerequisite. Today the challenge and proof flow assumes a privileged account. The student Google callback/native exchange completes a separate handoff. Extending the role check alone can either lock those users out or leave an unenforced admission path. The rollout needs browser and native challenge responses and sign-in completion before ordinary-role enrollment or mandatory policy can be enabled. The existing challenge store also binds credential changes, which requires coordination with Argon2id writes.

Use the existing encrypted TOTP and recovery primitives in the shared enrollment service. Require a recent admitted session to start enrollment, prove possession before activating the factor, acknowledge single-use recovery codes, then replace the old session with a factor-qualified one. For factor replacement and recovery-code regeneration, require verified current factor or approved account recovery, update the version under the account lock, revoke prior proofs and sessions, and write metadata-only events. Keep recovery material hashed and factor material under the reviewed wrapping key. Recovery support must independently verify occupational or student identity and must preserve administrator MFA.

The deployment policy should progress through instructor voluntary enrollment, institute-scoped readiness and then instructor enforcement. Students start with optional enrollment and separate institution-approved enforcement after accessibility, enrollment and recovery acceptance. Browser and native sign-in need a bounded pending challenge with no application session until completion. Federated authentication counts only for the assurance documented and validated by the LMS. Administrators and Super Users remain mandatory throughout.

The owner pilot must support manual entry, keyboard and screen reader use, recovery code storage and staffed loss recovery. Offer supported hardware or supervised options for users without a compatible personal smartphone. Make enrollment reminders accessible and consent-aware. Record only enrollment status, completion rates, recovery response times and access failures. The operator can pause a pilot mandate without removing factors, relaxing privileged admission or reusing revoked sessions.
