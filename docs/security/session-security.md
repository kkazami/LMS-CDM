# Session and cookie changes

Sprint 5 requires recent admission for revoking any other device as well as all devices. It rejects duplicate/ambiguous selectors and invalid UTC cutover timestamps. Ordinary current-device sign-out remains available. [Qualification and rehearsal dates](identity-rollout-qualification.md)

Keep opaque server-side sessions and the seven-day absolute and thirty-minute idle limits. The privacy page filters both deadlines and presents its existing minimal account-scoped session details. Individual and all-device revocation use a user-scoped predicate inside a transaction with the existing account lock. The server rechecks the selected session identity, expiry and applicable freshness before revoking. Sign-out from all devices requires a session created within five minutes. Its browser control clears both session cookie names after success. The session management path retains its existing role ceiling and native requests continue using bearer tokens.

Production rollout uses `SESSION_HOST_COOKIE_CUTOVER` as one shared ISO timestamp for the actual HTTPS origin. Set it only after all participating deployments can read both names. Before cutover the server writes `lumina_session`. From cutover it writes `__Host-lumina_session` and may read the legacy name during the existing seven-day maximum. Once the window expires, the legacy cookie is ineligible. Cookie creation uses Secure, HttpOnly, SameSite=Lax, Path `/` and no Domain for the host name. New writes and logout clear obsolete names. Local HTTP keeps the legacy name. The existing narrow challenge cookie remains separate.

The middleware routing hint, server credential selection, mutation-origin treatment, mobile WebView handoff and Electron startup recognize the new session name. Prefer the canonical cookie over legacy during transition. The server still validates selected tokens and does not extend session deadlines. For rollback use a forwarding revision that reads the canonical cookie. Avoid restoring an older deployment that only reads the legacy name. Verify existing HTTPS sign-in, refresh, logout and resume on real supported clients with synthetic staging identities before setting the production timestamp.
