# Engineering contract v2

This Markdown document explains a contract; it is never a gate or approval record.
Use the concrete examples in `.orchestra/harness/examples/` and schemas in `scripts/harness/contracts.ts`.

Record original scope and exclusions; REQ IDs; AC IDs with linked requirements and observable assertions; repository facts; original proposal; complete red-team findings; reasoned adjudication; exact planned paths; an ac-mapped task DAG; remediation finding IDs; commands with exact argv, coverage and expected test names; risk/operations; browser/database/security verification; environment; recovery.

Trace REQ → AC → task → named test → captured result → independent QA.
Authoritative artifacts live in the active run and are content-addressed by the controller.
HIGH/CRITICAL implementation approval follows reviewed planning. Deployment approval follows RELEASE_READY. A rubric score, checked box or agent consensus is not approval.
